## Global Constraints

- This is a repair sprint: change existing primitive contracts only where current behaviour is broken or insufficient for a readable guide (spec §1.3 scope boundary). Do not build `patternmap`, `cheatsheetgrid`, or `algorithmwalkthrough` — those are explicitly deferred (spec §6.4).
- Every new/changed visual contract owns its style purely through `RKTok*` tokens; primitive code owns geometry only (spec §2.1 "Theme ownership" row). New tokens go in `latex_templates/reportkit-core.sty` (as a `\rk@styletokenerror` fallback, in the existing "Structural chrome" block) **and** must be `\renewcommand`-ed in all three base theme files: `latex_templates/themes/reportkit-theme-default.sty`, `reportkit-theme-executive.sty`, `reportkit-theme-institutional-research.sty` (the `-paged`/`-slides` adapter files load these first and do not repeat algorithm tokens — do not add tokens there).
- Every shared algorithm state stays one of the existing nine words (`current, active, candidate, frontier, visited, resolved, discarded, blocked, unseen`) — do not invent new primitive-local states (this is why `dagstate`'s "ready"/"processed" map onto `frontier`/`resolved` rather than becoming new states; spec §4.2 note in the current file already documents this mapping).
- State/role meaning must survive grayscale: never rely on fill colour alone (spec §2.1 A3, §3.3 B3, §6.3 gate).
- Existing fixtures listed in `scripts/acceptance_check.sh`'s `TEST_TEXES` array must keep compiling and must not change their rendered geometry outside the documented fix (spec §6.3, last gate bullet). Run `bash scripts/acceptance_check.sh` before your final commit in every task.
- Compile checks use `lualatex`. If a task's environment lacks a `build/.venv-tests` virtualenv already set up, use the system `lualatex`/`pdflatex` on PATH directly for fixture compiles; pytest's `compile_doc` fixture (`tests/conftest.py`) skips cleanly if `lualatex` is unavailable, so prefer running the actual pytest suite when possible (`pytest tests/test_algorithm_*.py -q`) since it gives geometric pass/fail, not just "did it compile."
- Follow this repo's existing commit convention: `git commit` with a descriptive message ending in `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>` (see recent `git log` for tone/format — imperative present tense, e.g. "fix: ...", "feat: ...").
