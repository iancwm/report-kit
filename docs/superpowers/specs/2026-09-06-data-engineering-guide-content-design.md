## Why this is a separate spec from tooling

The publication review reads as a single punch list, but roughly half its
items are things the manuscript must *say* and the other half are things
`reportkit.cls` must be able to *do*. P0-02 ("force a page break before every
H1") is a class capability — content has no page-break control from Markdown.
P0-04 ("replace the draft footer") is a content decision — what string to put
there — riding on a class feature (`\setreportkitversion`) that already
exists. Keeping these together made every review item look like a build
change; separating them means most of this spec's sections can start
immediately, in parallel with tooling, while only the figure programme (§D)
is genuinely blocked.

## Non-goals

- Any change to `reportkit.cls`, any `.sty` file, or a build script. If an
  item needs one of those, it is the tooling spec's, and this document links
  to it instead of duplicating it.
- Rewriting sections' technical content. The manuscript prose is treated as
  final, per the existing visuals spec's precedent
  (`2026-09-05-data-engineering-guide-visuals-design.md`); this spec adds
  front matter, fixes two overflowing paths, adds captions/citations, and
  adds figures — it does not re-argue the pipeline's technical explanations.
- Building the PDF. Per the publication review's own handoff prompt: "Do not
  build the PDF unless explicitly asked; focus on source ... and reproducible
  build readiness." Verification below is source-level until a build is
  requested.

## B. Prose corrections — overflowing paths

*Source: P0-03. Priority: P0. No tooling dependency — this is a pure text
edit; tooling §B2's breakable-path macro is a defense-in-depth complement,
not a precondition.*

Both locations identified by the review are confirmed in the manuscript:

1. **`manuscript/02-ingestion.md:189`** (renders as page 16, step 4):
   ```
   `s3://crypto-lake/raw/trades/event_date=YYYY-MM-DD/event_hour=HH/part-<batch_id>.parquet`
   ```
   86 characters, unbreakable. Rewrite to the short logical form the review
   suggests:
   ```
   `s3://crypto-lake/raw/trades/{event_date}/{event_hour}/...`
   ```
   preserving the point being made (partition values derived from
   `event_timestamp` in UTC) in surrounding prose rather than in the URI
   itself.

2. **`manuscript/06-quality-reliability.md:159`** (renders as page 44, item
   8, the quarantine path):
   ```
   `s3://crypto-lake/quarantine/trades/event_date=YYYY-MM-DD/event_hour=HH/`
   ```
   Apply the same shortening convention, keeping this path visibly parallel
   to the raw path in §item 1 above (same bucket, same partition scheme,
   different prefix) since Section 6 draws the raw/quarantine contrast
   explicitly.

3. **Sweep for the same pattern elsewhere.** `03-storage.md:161` and `:236`,
   and `03-storage.md:246`, contain full or near-full `s3://` paths at
   moderate length (`s3://example-lake/...`, `s3://crypto-lake/raw/trades/...`,
   `s3://crypto-lake/curated/trades/`) that did not clip in the reviewed
   build but are the same shape of risk. Apply the same short-form convention
   for consistency; verify with the tooling gate (see below) rather than by
   eye.

**Acceptance:** no manuscript line contains an inline-code span the tooling
bounding-box check (tooling §D6) would flag; a 200–300 dpi render of the
affected pages, once available, shows every path in full within the margin.

### D5. Per-figure requirements (all new figures)

Each new figure needs, per the guidelines' Diagram Production Rules
(`publication-guidelines.md:333-390`) and the existing visuals spec's
established convention:

- a fragment at `fragments/fig-<slug>.tex` with exactly one
  `\begin{diagram}[...] ... \end{diagram}` block;
- a sentinel `[[REPORTKIT-VISUAL:fig:<slug>]]` inserted in its manuscript
  section at the point the guidelines specify;
- caption, `source={Author's synthesis.}`, and `description` (accessibility
  alt text) set in the diagram options — but note that setting `description`
  is **necessary and not yet sufficient**: the `diagram` environment currently
  stores the key and never emits it, so today's alt text reaches no reader.
  Tooling §B7 makes it load-bearing. Keep writing it; the acceptance below
  cannot be verified until B7 lands;
- a prose cross-reference immediately before or after the sentinel, per the
  guidelines' rule that the caption "explain the figure without requiring the
  paragraph that introduced it," while the surrounding prose still points the
  reader to it;
- for state/timeline/before-after figures specifically: no meaning conveyed
  by colour alone (per-node/per-panel labels and shape/line-style
  differences carry the semantics that colour reinforces).

**Acceptance:** total figure count lands in 16–19; every figure (existing and
new) has a caption, non-generic source statement, label, and a description
that is *recoverable from the built PDF* (requires tooling §B7);
every figure is referenced from nearby prose; at least one state-machine
figure, one before/after figure, and one two-track timeline figure exist,
satisfying the "varied grammar" requirement; no fragment uses a `\RKNode`
hand-placement workaround for a defect that tooling §C1 has fixed.
